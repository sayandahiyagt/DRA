# §38.5 Progressive-Interview A/B Proof (ledger)

Committed deterministic measurement summary for the §38.5 progressive-interview
A/B proof (mission `sayandahiyagt/dra#46` / PR #52, engine
`src/dra/progressive_interview.py`). The per-run runtime report
`progressive_interview_report.json` / `.md` written by the CLI is gitignored — see
`.gitignore` §38.5 block — so this directory holds the diff-stable ledger that
survives workspace resets, mirroring the `bake-off/` committed pattern.

## What it measures

The proof A/B-tests three interview strategies (dra#45) against a deterministic
12-topic oracle-user fixture corpus (seed=42, 6 recon perspectives) and the
five §38.5 metrics:

- user turns (per-topic average of `p1_questions + p4_questions` — question-count,
  not interrupt-round count);
- user abandonment / annoyance proxy (non-critical questions asked / 11);
- architecture-changing facts discovered late (late facts missed);
- research wasted on discarded branches;
- final handoff correctness (early + contextualised late facts / total facts).

## Decision rule (reverses ADR-005 to measured)

ADR-005 (use progressive clarification, not exhaustive up-front grilling) is
promoted from plausible architecture to **measured product policy** when the
proof verdict is `PASS`: progressive consumes fewer user turns than exhaustive
while matching handoff correctness. A `FAIL` verdict fires the ADR-005 reversal
trigger and reverses the decision — see `docs/adr/023_progressive_interview_proof.md`.

## Strategies

- `progressive` — objective + recon + focused p4 (`state['strategy']`,
  `control_plane.py:272`).
- `exhaustive` — the full 11-question §9.1 questionnaire.
- `minimal` — objective only, no p4 (the no-p4 lower bound).

## Run

```bash
# offline, always-green (no DB/network) — the sandbox gate
dra-progressive-interview --no-publish          # write + print report, exit 0 on PASS
dra-progressive-interview --dry-run             # print config + DB reachability, no run
uv run --extra dev pytest tests/test_progressive_interview.py -v   # 31 tests
```

## DB-gating / canonical staging

The 4 `TestProofDB` tests are `@pytest.mark.skipif` without Postgres
(`tests/_db.py:27`, `DB` mark → "No reachable Postgres..."). When Postgres is
reachable, `run_proof(publish=True)` stages per-strategy `MAINTAINER_ASSERTION`
rows + the A/B report into the standalone `user_assertion` table
(`0008_interview_constraints` migration, 26-char revision slug — the mission's
literal 38-char `0008_progressive_interview_constraints` overflows
`alembic_version varchar(32)`, see the migration docstring) and flips them
`staged → canonical` atomically via `publish.py` `_STANDALONE_STATE_TABLES`
(`("user_assertion",)`) — the bundle-scoped UPDATE mirror
(`publish.py:891-902`) that `_mirror_state_canonical` deliberately cannot reuse,
because `user_assertion` carries no `prov_entity` row and is kept outside
`entity_kind` (ADR-017).

## Deliverables

  `staged` stripped) regenerated by `run_proof(ProofConfig(), write=False, publish=False)`.
- `results.md` — human-readable outcomes table.
